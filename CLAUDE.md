# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **local-first** usage dashboard for Claude Code, Claude Cowork and OpenAI Codex (the ChatGPT desktop app's coding agent). The backend reads the logs those tools already write — `~/.claude`, the Cowork desktop root, `~/.codex` — and serves aggregated JSON; the React UI ("AI Usage") visualizes it. No login, and no transcripts or raw paths ever leave the machine. The only outbound calls reuse credentials already on disk, or are explicitly requested:

- Anthropic OAuth usage/profile (`/api/usage/live`, `/api/config`, `/api/accounts/live`) with Claude Code's stored token.
- ChatGPT `backend-api/wham/usage` and `/wham/profiles/me` with Codex's `auth.json` token (`/api/codex/live`, `/api/codex/profile`) — two GETs, never a token refresh, account id / e-mail stripped.
- A GitHub-raw `package.json` version check (`/api/version`, 30 min cache).
- A LiteLLM gateway's spend endpoints, only when one is configured.
- AI Insights model calls, **only when the user asks** (aggregates only; branch/churn panels redacted or refused for non-Anthropic providers).
- Anonymous PostHog analytics — opt-out, path-free (see `lib/analytics.ts` under Frontend).

## Commands

```bash
npm run dev          # backend (tsx watch, :8788) + Vite UI (:5180) via concurrently — 8788 so it can run beside Docker on :8787
npm run build        # tsc -b (typecheck, no emit) then vite build → dist/
npm run preview      # serve the built dist/ with Vite
npm run typecheck    # tsc -b (typecheck only, no emit)
npm test             # node:test unit tests (server/**/*.test.ts, run by tsx; no extra deps)
```

Docker (single Express process serves API + built UI on :8787, mounts the data folders read-only; published on `127.0.0.1` only unless `DASHBOARD_BIND` + `ALLOWED_HOSTS` opt into LAN access):

```bash
npm run docker:up    # docker compose up -d --build  (rebuild + restart after code changes)
npm run docker:down
npm run docker:logs
```

> **This app usually runs in Docker — there is no live/HMR refresh.** When running in Docker, after **every** code change you must run `npm run docker:up` to rebuild + restart, or the change won't be visible. The image installs `tsx` globally at build time (it is a devDependency; a local install under `NODE_ENV=production` installs nothing).

`docker:up` has a `predocker:up` hook running three host-side scripts:

1. `scripts/sync-macos-keychain.mjs` (macOS only) — copies the Claude.ai OAuth token from the Keychain into `~/.claude/.dashboard-oauth-cache.json`; see `readCredentials()` below for why.
2. `scripts/token-sync-agent.mjs ensure` (macOS only) — installs a **launchd LaunchAgent** (`com.claude-dashboard.token-sync`, log at `~/Library/Logs/claude-dashboard/token-sync.log`) that re-runs that sync every 15 min. Without it the cache is a one-shot snapshot whose access token expires within hours; the container re-reads the cache file on every request, so a host-side re-sync heals it with no rebuild. Manual controls: `npm run token-sync`, `token-sync:install` / `:status` / `:uninstall`. **Deliberately no in-container `refresh_token` flow** — Anthropic rotates refresh tokens, and a second consumer could invalidate the host's Claude Code login.
3. `scripts/write-host-repo-dir.mjs` (all OSes) — upserts `CLAUDE_JSON_HOST=~/.claude.json` (mounted at `/data/claude-json`; `workspace.ts` reads it through `CLAUDE_JSON` for the MCP inventory), **sets `CODEX_DIR_HOST=~/.codex` only if absent** when that folder has a `sessions/` dir, and **sets `TZ` to the host's IANA zone only if absent** (a blank `CODEX_DIR_HOST=` / `TZ=` is an opt-out and must survive).

Steps 1–2 are a no-op on non-macOS hosts (there, Claude Code refreshes `.credentials.json` itself).

There is **no linter** and only a `node:test` suite for pure server logic (`server/*.test.ts`, **synthetic fixtures only — never real transcripts**). Correctness is otherwise enforced by TypeScript `strict` plus `noUnusedLocals`/`noUnusedParameters` — a clean `tsc -b` and `npm test` are the bar. There is no CI typecheck (CI minutes cost money); run both locally. `scripts/snapshot-endpoints.mjs` + `compare-snapshots.mjs` diff endpoint output before/after a refactor.

### Pointing at a different data folder

`CLAUDE_DIR` overrides the scanned folder (default `~/.claude`). `COWORK_DIR` overrides the Cowork desktop root (OS-specific default — `coworkDir()` in `scan.ts`; auto-detected when present). `CODEX_DIR` overrides the Codex home (precedence `CODEX_DIR` > `CODEX_HOME` > `~/.codex`). From Codex, only `sessions/**/rollout-*.jsonl` enter the scan pipeline; `auth.json` (live limits token, never refreshed), `session_index.jsonl` (thread titles), `config.toml` (allow-listed keys only), `skills/*/SKILL.md` names, `plans/**/PLAN.md` and `automations/*/automation.toml` (name/status/schedule only) are also read — update the read-scope comment in `docker-compose.yml` when adding one. `SERVER_PORT` sets the backend port (default `8787`; `npm run dev` pins `8788`); `vite.config.ts` reads the same env var for its `/api` proxy target, so if you start `dev:server` and `dev:web` in separate shells give both the same value.

```powershell
$env:CLAUDE_DIR = "D:\backups\.claude"; npm run dev
```

In Docker, `~/.claude`, the Cowork root and `~/.codex` are mounted read-only at `/data/.claude`, `/data/cowork` and `/data/.codex` (`CLAUDE_DIR_HOST` / `COWORK_DIR_HOST` / `CODEX_DIR_HOST` in `.env`). The latter two are optional; unset, they fall back to the `.claude` mount and yield zero cowork/codex events (the codex `rollout-*.jsonl` name guard in `keepScanFile()` is what makes that fallback safe).

Frontend build-time vars (`VITE_*`, baked by `vite build` — in Docker via `build.args`): `VITE_DISABLE_ANALYTICS=1` ships a telemetry-free build; `VITE_POSTHOG_TOKEN` / `VITE_POSTHOG_HOST` override the analytics project.

## Architecture

Two processes in dev; one in Docker. The backend data flow is always **scan → cache → aggregate → endpoint**.

### The scan pipeline (`scan-pass.ts` → `merge.ts` → `data.ts`, cached by `event-store.ts`)

- **`scan-pass.ts`** — the only code that reads transcript JSONL. One walk of `scanRoots()`, one read, one `JSON.parse` per line, emitting flat per-file rows (`FileRows`) for both the usage events and the insights data, so the tabs can't drift apart. Pure extraction: **no cross-file reduction here.** A bounded pool of `PARSE_CONCURRENCY = 8` (the scan is CPU-bound on `JSON.parse`). Usage rows come from every file, **insight rows only from files ≤ `INSIGHTS_MAX_FILE_BYTES` (64 MB)**; Cowork transcripts get an empty `projectPath`. Codex rollouts are dispatched to `scan-pass-codex.ts`.
- **`merge.ts`** — pure, no I/O. Reduces rows into `UsageEvent[]` + `InsightsData`. **All dedup lives here:** ~28% of dedup keys appear in more than one file and many sessions span files, so per-file aggregates can never be pre-summed. `sessionsMeta` is derived here, never persisted. Claude project paths come from the transcript `cwd` (`project-path.ts`: drive letter lower-cased, `.claude/worktrees/<x>` folded into its repo; a session without a cwd borrows one recorded by another session in the same folder).
- **`data.ts`** — owns the pipeline and `getEvents` / `getInsights` (5 s TTL, single-flight). Caches parsed rows per file by `(path, mtime, size)`; skips `mergeRows` when nothing was reparsed, added or removed (`canReuseMerge`) but still refreshes `computedAt`. `dataFingerprint()` is a **memo token = data fingerprint + the current minute** (`MEMO_BUCKET_MS`), so memoised windows keep sliding while idle.
- **`builder-cache.ts`** — `memoBuilder(name, keyParts, token, build)`: endpoint outputs keyed by integer params × source, evicting the oldest entry past `MEMO_MAX = 256`. Key parts must be `intParam()`-clamped integers.
- **`event-store.ts`** — SQLite (`node:sqlite`, hence node 24) at `DASHBOARD_CACHE_DIR`, one JSON blob per file version; makes restarts cheap (~2.6 s in Docker). Fail-soft: without SQLite the app parses from scratch. **Bump `SCHEMA_VERSION` whenever what a parser emits changes** (shape *or* meaning), once per branch. **Opt-in history archive** (`DASHBOARD_RETAIN_HISTORY=1`, passed through compose): when a transcript disappears (Claude Code deletes them after ~30 days) its rows are slimmed (`slimRows`: no search corpus, error text or spawn descriptions — tool calls and error/rejection flags stay so archived sessions keep their counts) into `archived_files`, which schema bumps never wipe, and keep merging after the live files (live first — several session fields are first-file-wins); the archive is reduced once per archive state (`reduceArchive`) and each rescan settles only live rows against it. A file whose name is live at another path (a moved transcript) is never archived. A vanished file is archived only if its scan root still lists files (an unmounted volume must not archive or drop everything); archived Cowork/Codex rows count only while that root is configured, so `CODEX_DIR_HOST=` still opts out. `GET /api/archive`, `POST /api/archive/forget` (Settings button); an archived session's transcript answers `archived: true`.
- **`cache.ts` / `insights-scan.ts`** — thin facades over `data.ts` plus shared record types. Don't put scanning logic back into them.

> **In Docker the cache needs the `claude-dashboard-cache` named volume** (`docker:up` replaces the container). Deleting the volume is safe **unless the history archive is on** — then it also deletes the only copy of usage from transcripts Claude Code has already removed.

**History rows** (`LimitHitRow`, `RateLimitSnapRow`, `LineChangeRow`, `PrLinkRow`, `TurnRow`, `TitleRow` in `scan-pass.ts`) are per-item with their own key and are deduped and rolled up per session **only in merge.ts** (lines ± by tool_use/item id, PRs by URL, turns by prompt uuid / turn_id, limit hits by message uuid / turn_id); never pre-sum them per file. Title records have no timestamp — read before the timestamp skip, last in file order wins, a custom rename beats `ai-title` (Codex titles come from `session_index.jsonl` via `codex-titles.ts`). Claude turns are derived (prompt → last reply/tool line before the next prompt, capped at 6 h; a queued `isMeta` line after a limit refusal starts a new turn); Codex turns come from `task_complete.duration_ms`.

Parser rules worth not re-breaking:

- **Dedup tool calls by `tool_use.id`, never by `requestId:message.id`** — earlier lines for a message are streaming placeholders whose content arrives later; keying on the message silently drops most tool calls.
- **Split lines on `\n`, never with `readline`** — `readline` treats `U+2028`/`U+2029` (legal inside JSON strings) as line breaks and shreds records. This applies to every JSONL reader (`history.ts`, `subagents-live.ts`, `transcript.ts` already comply).
- **Usage dedup is by `requestId:message.id`** across all roots (`merge.ts::dedupUsage` keeps the row with the most effective tokens; key-less `':'` rows are all kept).

### Backend (`server/`, plain TypeScript run directly by `tsx` — never compiled, even in Docker)

- **`scan.ts`** — the `UsageEvent`/`UsageSource` types, path/root helpers (`claudeDir`, `codexDir`, `coworkDir`, `scanRoots`, `keepScanFile`), sidecar readers (`settings.json`, `stats-cache.json`, `usage-data/session-meta/*.json` — a missing dir is silent), credentials, and the outbound OAuth + LiteLLM calls. It does **not** read transcripts. **`readCredentials()`** reads both `.credentials.json` and `.dashboard-oauth-cache.json` (macOS Keychain copy, see `docker:up`) and returns whichever has the **latest `expiresAt`** (ties → `.credentials.json`), falling back to a live `security find-generic-password` (host/dev only). `fetchLiveUsage()` (30 s cache) and `fetchLiveProfile()` (30 min cache) share `oauthHeaders()`; the profile classifies `/api/config`'s `subscriptionType` (`pro`/`max_5x`/`max_20x`/`team`/`enterprise`/`free`). The live payload's `extra_usage`/`spend` (Anthropic's pay-past-your-limit credits) and `seven_day_breakdown` pass through to the UI.
- **Scan roots / `source`** — `<claudeDir>/projects` (`'code'`), the **Cowork** root when present (`'cowork'`: the desktop app's local agent mode writes standard Claude Code JSONL under `<coworkDir>/<acct>/<profile>/<sessionId>/.claude/projects/**`; `keepScanFile()` keeps only that segment; full-VM-sandbox runs aren't captured; Claude Chat has no local token data), and the Codex sessions root (`'codex'`).
- **Codex (`source: 'codex'`, `scan-pass-codex.ts`)** — rollouts at `<codexDir()>/sessions/YYYY/MM/DD/rollout-<local-iso>-<uuid>.jsonl`, parsed into the same `FileRows`. Rules:
  - Usage is **`token_usage_record.payload.usage`** deduped by `response_id`; **`input_tokens` includes `cached_input_tokens`** (`inputTokens = input − cached`, `cacheReadTokens = cached`, `cacheCreateTokens = 0`). Never sum `token_count.total_token_usage` / `turn_token_usage` / `thread_token_usage` (cumulative). CLI < 0.153 has no `token_usage_record` → `token_count.info.last_token_usage` keyed by `thread:ordinal`, never by timestamp.
  - Model and effort come from a two-pass `turn_id → turn_context` join (field `effort`, not `reasoning_effort`), falling back to `thread_settings_applied` then `world_state`.
  - A 140-char header regex (`HEADER_SCAN`) gates every `JSON.parse`; `compacted` lines (1–4 MB replays) are counted, never parsed; `item_completed` lines over `MAX_LINE_BYTES` are skipped; **no per-file size cap** (user threads are 7–60 MB).
  - Subagent threads (`thread_source: 'guardian_review'` or an object-valued `source`) fold into their parent as sidechains. The **guardian** is special: one long-lived reviewer answers many actions, so it emits **one review per `task_complete` verdict** (`outcome` allow/deny; a deny is a rejected `GuardianReview` call on the parent), model `codex-auto-review`, priced $0 (`hasPrice()` false). Other subagent kinds get one thread-level spawn of their kind.
  - A `declined` item is never a success or git commit/push; it is a user rejection only when the turn's `approvals_reviewer` is the user (under `auto_review` the guardian's verdict already counted it).
  - Tools come from `event_msg/item_completed` (PascalCase `item.type`, mapped to Claude tool names), never from `custom_tool_call` wrappers. Guardian rollout mtimes are frozen at creation, so liveness uses the last record timestamp and the fingerprint folds in total bytes. Project path = `session_meta.cwd`; branch/remote from `session_meta.git` when present.
  - **Live** (`codex-live.ts`): `GET chatgpt.com/backend-api/wham/usage` with `auth.json` + `ChatGPT-Account-Id` (30 s cache, PII stripped, windows classified by length). The passive fallback is the newest `token_count.rate_limits` whose `limit_id` is `'codex'` (skip `premium` probes), with a usage-limit error after it counting as reached; passive data carries `warning`, not `error`. **Never call the refresh flow.** `codex-config.ts` reads `config.toml` through a minimal allow-list TOML reader (MCP env/args/headers/tokens and project paths are never decoded).
- **Live agents** — `subagents-live.ts` (Claude; tail-reads recent transcripts, attaches workflow agents under `subagents/workflows/wf_*/` to their parent) and `codex-agents-live.ts` share one state machine (`mainAgentState()`): **waiting** (red) = pending approval, a user decline with no reply after it, or a failed turn; **your turn** = a cleanly finished turn (soft, never an alert); `counts.running` = running subagents + active/delegating mains on both endpoints. `workflows.ts` / `workflow-agent-detail.ts` / `workflow-script.ts` read Claude Code workflow journals.
- **`aggregate.ts`** — pure builders over `UsageEvent[]`: `buildRecent`, `buildWeekly` (+ `byModelEffective`, `codexSplit`, `firstEventTs`), `buildModels`, `buildActivity`, `buildTools`, `buildHourlyHeatmap`, `buildProjectStats`, `buildUsageSummary`, `buildEffort`, `computeCodexBlock`, plus `SourceFilter` / `sourceMatches` / `filterSource` (`'claude'` = everything but Codex). Insights builders live in `insights.ts` (over `InsightsData`, narrowed by `scopeInsights`); `contributors.ts` is the "what's contributing to your limits" breakdown (cost-weighted from the CLI's `attribution*` tags; Codex effective-token-weighted because guardian is $0). `transcript.ts` renders both platforms' transcripts; `sources.ts` summarises `/api/sources`.
- **`pricing.ts`** — regex→price table for the *estimated equivalent API cost* only (subscriptions have no per-token bill). **Order in `TABLE` matters** (first match wins): Fable 5.1 above `/fable/`, Mythos 5.1 above `/mythos/` (cache reads 0.25 vs 1.0), **Opus 5.5 (4 / 20, cache read 0.20) above `/opus-5/`**, which would otherwise match `opus-5-5`. OpenAI rows are standard-tier list prices (GPT-5.6/6 list a cache-write rate, but Codex never reports writes). **Adding or repricing a model** touches: `pricing.ts` (+ `pricing.test.ts`), `CostCalculation/utils.ts` `PRICING_DATA` (mirror it), `lib/palette.ts` (reuse a validated step or re-run the dataviz validator), and for Claude models `server/ai.ts` (`THINKS_BY_DEFAULT` / `ALWAYS_THINKS` — always-thinking models get `THINKING_HEADROOM` — and `DEFAULT_MODEL`) + `useAiConfig.ts` `PROVIDER_MODELS`.
- **AI Insights** (`ai.ts`, `ai-context.ts`, `ai-datasets.ts`, `ai-router.ts`) — backends in order: API key / proxy (`ANTHROPIC_*`), the `claude` CLI, the Claude.ai OAuth token, or the user's OpenAI/Gemini key from Settings. Context and prompts are **scoped to the platform** (Codex limits come from `fetchCodexUsage`; Claude-only datasets are unavailable under Codex). Payloads are aggregates only; branch names and file paths are redacted (chat) or refused (per-section ✨) for non-Anthropic providers. Section payloads are capped at 64 KB.
- **`index.ts`** — Express routes, every response wrapped as `{ data, computedAt, claudeDir }`. Numeric query params go through **`intParam()`** (integers, clamped: `hours` 1–72; `days` 7–365 = `MAX_WINDOW_DAYS` on `/api/usage/weekly` and `/api/usage/litellm`; 1–31 models/tools; 7–180 activity; 7–365 heatmap/projects; 1–90 insights). `?source=all|claude|code|cowork|codex` (`parseSource`) scopes usage, activity, tools, heatmap, projects, sessions, search and insights routes. **`GET /api/sources`** reports per-surface lifetime event counts, `cowork.available`, `codex.available` and each data dir — the frontend gates all Cowork UI on the first and the platform switcher on the second, so Code-only users see the original dashboard. LiteLLM spend is fetched as a short range (previous month → today) or, only for longer windows, the last 365 days — each cached and single-flight; a page-capped fetch is flagged `truncated`. When `dist/` exists it also serves the UI with an SPA fallback.
- `workspace.ts` (tasks/plans/plugins/MCP/skills per platform), `history.ts` (`history.jsonl` slash commands), `version.ts` (update check; dev-only `POST /api/update/pull`).

### Security boundary (`http-guard.ts`)

The API serves transcripts and can spend the user's Claude quota (AI Insights), so it stays local: the server listens on `127.0.0.1` outside Docker (`BIND_HOST` overrides; the Dockerfile sets `0.0.0.0` and compose publishes `${DASHBOARD_BIND:-127.0.0.1}:8787`); every request's **hostname** (never port — the Vite proxy uses `changeOrigin: false`, so the backend sees the browser's `Host: localhost:5180`) must be localhost / 127.0.0.1 / ::1 or in `ALLOWED_HOSTS`; every non-GET must be `application/json` with an allowed `Origin` if one is sent. Those checks defend **browsers** (DNS rebinding, forged forms) and are not access control — only the loopback bind keeps the API local. `/api/config` returns an **allow-list** of settings fields (`publicSettings()`) — never spread `settings.json` (it can hold `env` API keys, `apiKeyHelper`, hook commands). AI Insights' `claude --print` runs as a plain completion — `--tools ""`, `--strict-mcp-config`, `--safe-mode`, cwd `os.tmpdir()`, `NoDefaultCurrentDirectoryInExePath` — because its prompt carries repo-derived strings; a CLI that rejects `--tools` / `--strict-mcp-config` fails closed. `--no-session-persistence` keeps the dashboard from counting its own calls. Gemini keys go in `x-goog-api-key`, never the URL.

### Domain rules to preserve

- **Effective tokens = input + output + cacheCreate.** Cache *reads* are excluded (they don't count toward rate limits). `totalTokens` includes them; charts and shares plot effective tokens, totals appear in tooltips.
- **The Claude "current 5-hour block"** is anchored on the **most recent `sessionId`** (Anthropic starts a window at a session's first message) and **rolls inside that session**: the first message at or after a window's end opens the next one. `prevTotals` is the window before (earlier in the session, else the previous session's last window). Codex events never anchor it.
- **The Codex block** (`computeCodexBlock`, `/api/codex/block`, never memoised) is the provider's window: 5-hour, else weekly; start = reset − window length, previous = the same length before. With no reset time it rolls account-wide from the first Codex event.
- **The binding limit** shown in the sidebar badge, tab title and alerts is the fuller of a platform's 5-hour and weekly windows (100 once the provider says reached); under Both, the max across platforms. Thresholds 70/90 come from `lib/limits.ts` (`limitTone`) everywhere.
- **Weekly reset** falls back to the next Monday 01:00 UTC (`nextMondayReset`); live `seven_day.resets_at` wins wherever available.
- `<synthetic>` and zero-token models are filtered out of model shares.
- The activity heatmap is derived **live from events**, falling back to `stats-cache.json` only for days with no live data — and **only for sources that can contain Claude Code** (`statsCacheApplies()`); Codex/Cowork heatmaps never get it.
- **Day buckets are calendar days** (`localDayStarts()`), not 24 h steps — a DST change must not shift or duplicate a day. `/api/activity?utc=1` buckets by UTC day (to match OpenAI's server series).
- **Rejections** are `is_error` tool results whose text starts with Claude Code's decline wording (`isRejectedToolResult()`, shared with `subagents-live.ts`); Codex: a user-declined item or a guardian deny. Failure rate never counts rejections.
- **Per-day averages** divide by the days since the earliest logged event when history starts inside the window (`lib/coverage.ts`, `firstEventTs`), else by the window.

### Frontend (`src/`)

- **`App.tsx`** is a thin shell: `Sidebar` (brand **"AI Usage"**, the active platform's data dirs), a header (agent traffic signal, platform switcher, surface toggle — hidden on Agents — `LiveBadge`) and the active tab. Ten tabs (Live Usage, Agents, Workflows, Trends, Models, Insights, Workspace, AI Insights, Sessions, Settings — `settings` stays last), routed by path (`/<tabId>`, unknown → `live`), each **`React.lazy`** behind one `<Suspense>` (`manualChunks` splits `recharts`/`posthog`/`react`; tabs use named exports remapped in `lazy()`). The empty state comes from `/api/sources` lifetime counts for the selected platform (Live stays when live limits exist); a failed `/api/sources` shows an error card. Each data source is an independent `usePolling` call — no global store.
- **Platform vs surface (`hooks/useSource.tsx`)** — the **platform** switcher (Claude / Codex / Both) renders only when `codex.available`; there is deliberately **no Codex tab**. **Every tab renders the same components in the same layout for every platform** — Codex-only data sits on the tab it belongs to with a Claude equivalent (and vice versa), under Both the same components side by side or with a split, and no Claude wording appears under Codex. `tabsFor()` drops only Workflows, and only under Codex. A Codex-only user starts on Codex. The **surface** toggle (Code / Cowork / All) is the Claude-side sub-filter, shown only when `cowork.available` and the platform is Claude. `withSrc()` maps the pair to `?source=claude | code | cowork | codex`, or no parameter under Both — so a user with neither Cowork nor Codex gets byte-for-byte the original URLs. Gate Codex UI on `platform`/`showCodex`, never on the surface filter. Polls with an explicit scope: `liveWeekly` (fixed 7-day fast poll for Live, budgets, alerts), the Both-only `?source=claude` / `?source=codex` weekly polls in Trends, per-platform `LimitsContributors` under Both, and `useBudgetAlerts`' per-platform polls.
- **`hooks/usePolling.ts`** — fetch-on-interval returning `{ data, computedAt, claudeDir, error, loading, lastFetch }`. Deliberate: a module-level **in-flight map** collapses concurrent requests for a URL; a response cache re-shows a URL's last data only while it is younger than 2 × its interval; an **empty URL disables** the poll (the gating idiom); polls **pause while `document.hidden`** with a catch-up tick; a per-effect cancel flag drops a stale URL's late response; and deliberately **no `AbortController`** (it would cancel the shared request for other subscribers).
- **`hooks/useLimits.ts`** — per-platform USD caps `{claude, codex}` in `localStorage` (`claude-dashboard-limits-v3`, migrated once from `-v2`); client-side only. Alerts: `useLimitAlerts` (rate limits, every tab; settings `limitAlerts`) and `useBudgetAlerts` (caps, per platform).
- Components live in `components/design-system/{atoms,molecules,organisms}/` (atomic design): one folder per component with `Name.tsx`, `types.ts`, `utils.ts` and — atoms only — `Name.variants.ts` (`class-variance-authority`). Reuse `ProgressBar`, `ToggleGroup`, `Badge`, `LegendDot`, `StatCard`, `InfoTip` (atoms) and `Section`, `ChartTooltip`, `HoverTooltip`, `ExportButton` (molecules). Cross-folder imports use `@/` (→ `src/`); same-folder imports stay relative. Heavy charts (`UsageBarChart`, `PlatformDailyCompareChart`) are `React.memo` — the live context changes about once a second.
- `lib/format.ts`, `lib/palette.ts` (per-model colours, validated — see its header), `lib/limits.ts`, `lib/coverage.ts`, `lib/platform.ts` (`titleScope`, platform nouns) are shared helpers. Charts use `recharts`; Tailwind with a custom `ink`/`clay` palette.
- **`lib/analytics.ts`** — anonymous PostHog (`posthog-js` + `@posthog/react`, provider in `main.tsx`): path-only pageviews and a fixed event set — `app_opened`, `tab_viewed`, `source_changed`, `platform_changed`, `insight_range_changed`, `export_clicked`, `ai_insight_clicked`, `ai_chat_asked` — with super-props `app_version`, `plan`, `usage_mode`. **Autocapture and session replay are disabled.** Never pass paths, cwd, session IDs, titles or transcript text to `track()`. `analyticsEnabled()` requires a PROD build, `VITE_DISABLE_ANALYTICS !== '1'`, a real token (not `PLACEHOLDER_TOKEN`), and no user opt-out (`claude-dashboard-analytics-optout`, Settings → Telemetry).
- `types.ts` mirrors the backend's shapes — change both together.

## Conventions

- Server files import each other with explicit `.ts` extensions (`./scan.ts`) — required by `allowImportingTsExtensions` + `tsx`.
- New `/api/usage/*` data flows through `getEvents()` (never re-scan disk) and returns via `wrap(...)`; numeric params through `intParam()`.
- **Versioning:** every same-repo PR into `main` gets a CI patch bump + an AI-drafted CHANGELOG entry (`.github/workflows/version-bump.yml`); never bump by hand there. **Fork PRs** can't be pushed to by that job — bump `package.json` and write the CHANGELOG entry manually. When branches are stacked, merge `origin/main` into the next branch before pushing it and take main's side on `package.json`/`CHANGELOG.md`; PRs merge with merge commits.
